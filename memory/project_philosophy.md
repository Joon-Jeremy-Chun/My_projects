# 목적과 선택 이유

## 2026-10-20 — 상세 정리와 검증 가능한 보완

[팩트] 사용자는 이전 MultiCampus 저장소와 같이 My_projects도 세세하게 정리하도록
요청했고, 이어 "미완성과 오류 고쳐서 올려줘 내가 나중에 확인할께"라고 요청했다.
문서·구현·회귀 검증·commit/push까지 이번 범위에 포함한다.

[추론] 넓은 수학 자료는 루트 → 분야 → 연구/연습 가이드 → 실제 코드의 네 층으로
읽는 것이 적절하다. 60개 README와 전체 코드 목록으로 탐색을 개선하고 기존 파일은
이동하거나 삭제하지 않는다. 공개 문서는 영어를 유지하고 근거·재현 한계를 연결한다.

채택한 보완 원칙:

- 주석뿐인 파일은 명시적인 가정의 작은 참조 구현으로 완성한다.
- 오류 검증은 해석해, 보존 법칙, 잔차, 알려진 적분, 의미 있는 통합 fixture를 사용한다.
- 과거 그림·CSV·논문 수치와 새 구현/검증을 구분한다.
- 실험적 설계를 검증된 임상·정책·투자 성과로 확대하지 않는다.
- 사용자 기존 변경과 미추적 파일을 보호하기 위해 별도 worktree를 사용한다.
- 게시 제한 때문에 로컬 역사를 지우거나 재작성하지 않는다. 최종 트리를 원격의
  기존 이력 위에 연결하는 게시 커밋으로 전달한다.

개인 역할은 코드·기록·공식 출판에서 확인된 수준만 적는다.
이력서 원본과 연락처를 공개 자산으로 복사하지 않는다.
