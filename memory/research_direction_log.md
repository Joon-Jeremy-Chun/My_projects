### 게시 방식 조정

[팩트] 게시 전 객체 검사에서 미게시 이력에 100MiB 초과 CSV가 발견됐다.

[추론] 기존 로컬 이력과 원격 이력을 재작성하지 않고 현재 완성된 트리를
origin/master 위의 새 게시 커밋으로 전달한다. 이 방식을 사용자에게 공유했다.
14개 로컬 커밋의 식별자와 원래 미커밋 작업은 보존한다. 게시 후 원격 SHA를 검증한다.

원래 작업 폴더의 기준 hash와 대조해 기존 파일 내용이 보존됐음을 확인했다.

### 게시 완료

[팩트] 검토한 수정은 `d1dbfc7`로 보관했다. 원격 기존 master `58a5121` 위에
최종 트리만 전달한 게시 커밋은 `5b2833eb68a75399a9239b816ec6206b66f5e9be`다.
두 커밋의 트리는 `4410cd1774f8fb26a245a34962a6776e521e0c42`로 정확히 일치한다.
게시 대상으로 추가되는 객체 260개 중 최대 blob은 5,539,328바이트였다.
일반 push가 성공했고 `git ls-remote --heads origin master`로 원격 SHA 일치를 확인했다.
기존 원격 이력의 fast-forward이며 force-push나 이력 재작성은 하지 않았다.

[팩트] 게시 후 원래 작업 폴더의 1,385개 파일 SHA-256을 기준 기록과 재대조했다.
변경 0개이며 HEAD, Git 작업 상태, 미추적 파일 집합도 모두 기준과 일치했다.

[팩트] PDF의 전역 textconv 설정이 diff를 텍스트로 바꾸므로, 최종 트리 전달에는
`git diff --no-ext-diff --no-textconv --binary --full-index`로 만든 패치를 사용했다.
검토한 수정의 공백 검사는 통과했다. 이전 미게시 이력에 이미 있던 공백 진단은
그대로 보존했으며 이와 무관한 과거 파일을 일괄 정규화하지 않았다.

원래 로컬 master와 미커밋 작업은 보존했다. 이후 작업은 검증된 원격 master 또는
`codex/portfolio-publish-20261020`에서 시작한다. 이 완료 기록은 별도 문서 커밋으로 게시한다.
