# Shared Agent Instructions — My_projects

This contract applies to Claude, Codex, and other agents in this repository.
Tool entry points: [CLAUDE.md](CLAUDE.md), [CODEX.md](CODEX.md).

## Purpose

Maintain a detailed, attractive, evidence-backed computational mathematics
portfolio. Explain research, coursework, teaching materials, and experiments at
their actual level of completion. Preserve attribution and historical results.

## Communication and evidence

- Speak naturally and politely in Korean with the owner.
- Use `[팩트]` for verified observations, `[추론]` for interpretation, `[주의]`
  for material operational risk, and `미확인` for unknowns.
- Distinguish original source, saved outputs, a fresh run, a publication, and
  the current GitHub state. A filename, static parse, or plot does not establish
  a theorem, predictive performance, clinical validation, or deployed behavior.
- English public READMEs are the established default. Instructions and the short
  memory index use English; owner-facing records and handoffs use Korean.

## Start and preserve

Read this file, the tool entry point, [memory/MEMORY.md](memory/MEMORY.md), current
task status, and the latest relevant handoff. Check Git status, branch, remote,
and the actual files before edits. Preserve pre-existing changes.

Communicate the understood objective and exact intended changes before side
effects. Explicit edit/publication authorization persists within its scope;
do not ask for the same permission again. The owner's 2026-10-20 request
authorizes completing unfinished code, fixing errors, documenting the work,
and committing/pushing the reviewed result for later review.

Do not delete/move originals, clear notebook outputs, or rewrite Git history as
routine cleanup. Historical figures remain historical after a code correction.
Record corrected behavior and new assumptions separately; do not silently
present a new model choice as the original author's completed research.

## Code and numerical work

- Inspect top-level effects before running or importing scripts. This archive
  includes API calls, crawlers, market-data streams, output writes, long grids,
  and drone commands. Documentation/repair authorization does not authorize
  broker actions or actual drone flight.
- Prefer focused tests with analytical solutions, conservation laws, known
  residuals, or meaningful fixtures. Do not claim all experiments reproduced
  from a static audit or a small smoke suite.
- Verify units, state ordering, population normalization, numerical step sizes,
  boundary signs, optimization constraints, and train/validation separation.
- Keep new demos deterministic where practical. Use temporary output locations
  for tests; do not overwrite archived evidence while verifying fixes.
- Check dependencies against actual runs; do not invent historical version pins.

## Documentation

Root README is the portfolio entry point. Collection and project guides explain
the problem, method, data/parameters, actual role, source files, reading order,
outputs, limitations, and execution preparation. Link directly to real paths.
Keep comprehensive source inventories separate from the root introduction.

Use original figures with provenance and clear captions. Decorative covers are
illustrations, not data. Keep private résumé PDFs, contact details, credentials,
and private workstation paths out of newly authored public material.

## Git and completion

- Recheck branch, remote, and incoming history before Git writes. Compare
  ancestry; different hashes alone do not establish which branch is ahead.
- Stage explicit reviewed paths only; never `git add .` or `git add -A`.
- Inspect the full diff, staged filenames, and cached diff before committing.
- Preserve unrelated local work and record any isolated worktree used.
- No force push, destructive reset, or history rewrite for routine organization.
- Verify remote HEAD after publication; local changes, commits, and pushes are
  distinct states. Update task status, decisions, and a topic handoff.

Add coordination infrastructure or delegate only when explicitly authorized.
